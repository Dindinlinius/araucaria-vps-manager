# Araucaria VPS Manager

Araucaria VPS Manager — установщик и консольные команды для **Xray-core с VLESS + REALITY** на новом VPS под Ubuntu. Он настраивает подключение без Docker, 3x-ui и веб-панели, защищает SSH с помощью Fail2ban, настраивает UFW и выдаёт ссылку, которую можно импортировать в Hiddify или другой совместимый клиент.

Проект рассчитан на владельца одного VPS, которому нужен воспроизводимый способ развернуть и обслуживать одно VLESS-подключение без ручного редактирования JSON.

> **Статус:** кандидат к публичному тестированию. Стабильный релиз 1.0 пока не выпущен. Автоматические тесты не заменяют проверку установки на чистом VPS и реального подключения клиента.

## Что делает установщик

При первом запуске на чистом сервере Araucaria:

1. Проверяет версию Ubuntu, наличие systemd и доступ root. Определяет текущий и настроенные SSH-порты.
2. Обновляет пакеты Ubuntu и устанавливает необходимые системные инструменты.
3. Настраивает **UFW**: разрешает обнаруженные SSH-порты и выбранный TCP-порт Xray. Для нового, ранее не настроенного UFW устанавливает запрет входящих соединений по умолчанию.
4. Включает **Fail2ban** для SSH. Стандартный режим — 5 неудачных попыток за 10 минут, блокировка на 12 часов.
5. Устанавливает официальный **Xray-core**, создаёт одного клиента **VLESS + REALITY + Vision**, генерирует UUID, ключи REALITY и Short ID.
6. Запускает Xray от отдельного непривилегированного системного пользователя `araucaria-xray`.
7. Включает ежедневные автоматические обновления безопасности Ubuntu (без автоматической перезагрузки).
8. Устанавливает команды управления, проверяет службы и выводит VLESS-ссылку для импорта в клиент.

По умолчанию REALITY использует `www.google.com:443` как целевой TLS-сайт. Внешний TCP-порт выбирается случайно из диапазона **1024–65535** с проверкой занятых и зарезервированных портов.

Установщик также добавляет жёлтое приглашение `root@hostname` в `/root/.bashrc`. Это только оформление командной строки Bash; параметры доступа по SSH не меняются.

## Требования

- **Чистый VPS** с Ubuntu **22.04 LTS** или **24.04 LTS** и systemd.
- Доступ `root` по SSH. Желательна аварийная консоль в панели провайдера.
- Доступ из VPS к репозиториям Ubuntu, GitHub и выбранному TLS-сайту REALITY.
- Внешний IPv4-адрес, доступный для подключения с устройства пользователя.
- Если у провайдера есть собственный файрвол или Security Group, входящий TCP-порт Xray нужно разрешить **также в панели провайдера**.

**Не устанавливайте Araucaria поверх существующего Xray.** Скрипт рассчитан на первичную настройку и останавливается при обнаружении ранее установленного Xray или собственных файлов Araucaria. Он не является средством миграции или переустановки «поверх».

## Установка

### Из публичного GitHub-репозитория

После публикации проверенной версии достаточно подключиться к **новому** VPS под `root` и выполнить:

```bash
apt-get update && apt-get install -y git
git clone https://github.com/Dindinlinius/araucaria-vps-manager.git
cd araucaria-vps-manager
bash install.sh
```

**Пока репозиторий приватный**, HTTPS-клонирование без авторизации не сработает. Для тестирования нужен доступ к репозиторию, например read-only Deploy Key и SSH-клонирование. Эти команды будут применимы без ключа после перевода репозитория в публичный режим и переноса проверенного кода в `main`.

Для официальных релизов рекомендуется устанавливать **конкретную версию (Git tag)**, а не постоянно изменяющуюся ветку `main`. Однострочный способ установки появится после финальной проверки релизной сборки.

### Что спросит установщик

В начале можно задать имя профиля (по умолчанию `USAraucaria`; допускаются русский язык, пробелы и эмодзи). Затем программа покажет план: SSH-порты, порт VLESS, REALITY-сайт и режим Fail2ban.

Проверьте, что среди SSH-портов есть порт **текущего подключения**, и подтвердите установку словом `yes`. До проверки второго SSH-входа **не закрывайте первую сессию**.

После успешной установки появятся три отдельных раздела: выполненные действия, готовая VLESS-ссылка и команды управления. Скопируйте ссылку целиком в Hiddify и проверьте подключение.

> Если после установки изменились пакеты ядра, Ubuntu может потребовать перезагрузку. Сначала убедитесь, что повторный SSH-вход работает.

### Параметры установщика

| Параметр | Действие |
| --- | --- |
| `--name "Мой VPN"` | Имя профиля в ссылке |
| `--port 56399` | Использовать указанный TCP-порт вместо случайного |
| `--target www.google.com` | TLS-сайт REALITY |
| `--ssh-port 2222` | Дополнительно разрешить SSH-порт, который не удалось определить автоматически |
| `--strict-fail2ban` | Строгая защита SSH: 2 попытки за 3 минуты, блокировка на 72 часа |
| `--no-upgrade` | Не выполнять полное обновление установленных пакетов Ubuntu |
| `--yes` | Не спрашивать интерактивное подтверждение |
| `--help` | Справка |

Пример: `bash install.sh --name "Home VPS" --port 56399`.

Режим `--strict-fail2ban` не рекомендуется без аварийной консоли: легко заблокировать собственный IP после нескольких ошибок входа.

## Управление VLESS

После установки следующие команды доступны под `root`:

| Команда | Назначение |
| --- | --- |
| `vless-link` | Показать текущую VLESS-ссылку без изменения настроек |
| `vless-name` | Изменить имя профиля через ввод |
| `vless-name "Мой VPN"` | Сразу назначить новое имя |
| `vless-port` | Выбрать новый порт: случайный или указанный вручную |
| `vless-port --random` | Выбрать случайный свободный TCP-порт |
| `vless-port 38421` | Установить конкретный порт |
| `vless-rotate` | Сгенерировать новые UUID, ключ REALITY и Short ID |
| `araucaria status` | Проверить состояние Xray, UFW и Fail2ban |
| `araucaria xray check` | Проверить доступную стабильную версию Xray |
| `araucaria xray update` | Обновить Xray с проверкой Hiddify и откатом |
| `araucaria xray rollback` | Восстановить прежний Xray после прерванного обновления |
| `araucaria commands` | Показать список команд |
| `araucaria --help` | Справка по командной строке |

**Переименование** меняет только название после `#` в VLESS-ссылке. Порт и ключи остаются прежними, Xray не перезапускается. Чтобы увидеть новое имя в Hiddify, переимпортируйте ссылку или переименуйте профиль в самом клиенте.

**Смена порта** обновляет конфигурацию Xray и локальные правила UFW: сначала разрешает новый TCP-порт, проверяет переключение и только после этого удаляет старое правило. При сбоях предусмотрен откат, но его успех не гарантируется во всех аварийных ситуациях. После успешной смены порта **нужно импортировать обновлённую ссылку в клиент**. Внешний файрвол провайдера автоматически не меняется.

**Смена ключей** (`vless-rotate`) отзывает прежние параметры доступа: старые ссылки перестанут работать. Команда создаёт резервную копию и выдаёт новую ссылку. Не запускайте её, если сейчас нет возможности обновить настройки клиентов.

Если автоматическое определение IP не сработало:

```bash
vless-link --ip ВНЕШНИЙ_IP_VPS
```

Аналогичный параметр `--ip` поддерживают `vless-rotate`, `vless-port` и `vless-name`.

## Обновление Xray с подтверждением

Araucaria не обновляет Xray автоматически в фоне. Для обновления используется отдельная команда, которая требует интерактивного терминала и подтверждения пользователя.

```bash
araucaria xray check       # Проверить доступную стабильную версию
araucaria xray update      # Установить обновление и проверить VPN
araucaria xray rollback    # Восстановить предыдущую версию после прерванного обновления
```

`araucaria xray update` проверяет наличие более новой **стабильной** версии Xray-core в официальном GitHub-репозитории XTLS. Если обновление есть, программа:

1. Спрашивает разрешение на обновление и предупреждает о кратком прерывании VPN.
2. Скачивает официальный архив для архитектуры сервера вместе с контрольной суммой `SHA-256` и проверяет их совпадение. Проверка суммы помогает выявить повреждённую загрузку, но сама по себе не заменяет криптографическую проверку подлинности издателя.
3. Проверяет новую версию с **текущей** конфигурацией до её применения. Сохраняет предыдущий исполняемый файл Xray и отдельную копию конфигурации.
4. Заменяет **только исполняемый файл Xray**, перезапускает службу и проверяет, что прежний TCP-порт слушается. UUID, REALITY-ключи, имя профиля, порт, UFW и Fail2ban не меняются.
5. Показывает состояние VLESS-ссылки. Обычно она **не меняется**, так как её параметры остались прежними.
6. Просит пользователя проверить Hiddify **на другом устройстве или в клиентском приложении**, пока SSH-сессия остаётся открытой.

В терминале появится вопрос: **«ВПН работает?»**. Ответ `yes` сохраняет новую версию. Ответ `no` запускает автоматическое восстановление прежнего бинарника Xray и перезапуск службы; после этого также нужно перепроверить подключение. Значения `yes` и `no` выделяются синим цветом.

Если перезапуск новой версии неудачен, программа тоже пытается автоматически вернуть предыдущую. При прерывании SSH-сессии предусмотрена попытка отката. При внезапном завершении процесса (например, `kill -9` или отключение питания) автоматически выполненный откат не гарантируется: на диске остаются резервная копия и метка незавершённого обновления. После повторного SSH-входа проверьте состояние и выполните `araucaria xray rollback`, если требуется.

**Ограничения:** восстановление прежнего бинарника и локальной службы не гарантирует доступность VPN из каждой сети. В версии для тестирования автообновление рассчитано на Linux x86_64 и aarch64. Геоданные и служебные файлы systemd этим действием не обновляются. Не запускайте обновление без доступа к аварийной консоли провайдера.

## Безопасность и ограничения

- **Araucaria не меняет SSH-пароль, не запрещает вход под root и не отключает авторизацию по паролю.** Если сервер доступен из интернета, рекомендуется отдельно настроить вход по ключу и ограничить SSH-доступ.
- Случайный порт, VLESS и REALITY **не гарантируют** отсутствие блокировок или обнаружения трафика.
- Готовая `vless://`-ссылка предоставляет доступ к подключению. Не публикуйте её, UUID, приватный ключ REALITY или `config.json`.
- Установщик выполняется с правами `root` и скачивает официальный установщик Xray из ветки upstream GitHub. **В текущем кандидате источник Xray не закреплён за неизменяемой версией.** Перед стабильным релизом требуется фиксировать и проверять используемые внешние компоненты.
- Обновления безопасности Ubuntu включены, но **сам Xray не обновляется автоматически**.
- Поддерживается одна конфигурация VLESS + REALITY с одним пользователем. Веб-панели, Trojan, управление несколькими пользователями и автоматическое создание правил в панели VPS-провайдера не входят в состав проекта.
- Успех локальной проверки Xray не означает, что TCP-порт доступен через все сети: проверьте подключение с устройства за пределами VPS.

## Диагностика

Если клиент не подключается, сначала проверьте TCP-доступность порта с клиентского устройства и правила внешнего файрвола провайдера. На VPS полезны команды:

```bash
araucaria status
systemctl status xray --no-pager -l
journalctl -u xray -n 50 --no-pager
ufw status verbose
fail2ban-client status sshd
ss -ltnp
```

Проверка конфигурации Xray:

```bash
xray run -test -config /usr/local/etc/xray/config.json
```

При сбоях установки Araucaria выводит проблемный этап и рекомендации. Для части операций (`apt`, TLS, UFW, Fail2ban, установка Xray) можно исправить причину и повторить конкретный шаг в текущем процессе. **Критические ошибки не пропускаются:** частично установленный Xray или нарушенные права файлов требуют ручной диагностики. Не запускайте `install.sh` повторно поверх неполной установки без выяснения причины. Сохраняйте текущую SSH-сессию до восстановления доступа.

После установки жёлтое приглашение Bash в уже открытом окне можно включить командой `source /root/.bashrc`. При следующем SSH-входе оно появится автоматически.

Если обнаружили воспроизводимую ошибку, создайте [Issue](https://github.com/Dindinlinius/araucaria-vps-manager/issues) с версией Ubuntu, описанием действий и логами. **Удалите из логов IP-адреса, ссылки, UUID и секреты**, если не хотите делать их публичными.

## Где находятся настройки

| Путь | Содержимое |
| --- | --- |
| `/usr/local/etc/xray/config.json` | Рабочая конфигурация Xray, содержит секреты |
| `/etc/araucaria/settings.json` | Имя VLESS-профиля |
| `/var/backups/araucaria/` | Резервные копии конфигурации |
| `/usr/local/bin/araucaria` | Основная программа управления |
| `/usr/local/bin/vless-*` | Команды-ярлыки управления |
| `/etc/fail2ban/jail.d/araucaria-sshd.local` | Параметры защиты SSH |
| `/etc/systemd/system/xray.service.d/20-araucaria-hardening.conf` | Ограничения прав службы Xray |
| `/root/.bashrc` | Настройка приглашения Bash |

## Разработка и тестирование

Проект написан на Bash и Python 3; дополнительные Python-библиотеки для управляющей программы не требуются.

Проверки без установки на VPS:

```bash
bash -n install.sh
python3 -m py_compile araucaria.py
python3 -m unittest discover -s tests -v
```

GitHub Actions запускает тесты на Ubuntu 22.04 и 24.04. Эти тесты проверяют логику и обработку ошибок с имитацией системных команд; они **не подтверждают** корректность всех сценариев на реальном VPS. Перед стабильным релизом необходим отдельный полный прогон установки, смены порта и ключей, проверка Hiddify и повторного входа по SSH.
